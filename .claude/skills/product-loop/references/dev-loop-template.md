# Dev loop template (`docs/intent/dev-loop.md`)

Copy this, fill it in, roast it, then get the owner to confirm. CC Bill's filled-in version is `docs/intent/dev-loop.md`.

## Goal
Whatever ships behaves as specified, and every scenario has an automated test. Tokens are spent only where a deterministic tool can't do the job. The owner reviews no code and only presses **Release**.

## Roles
| Role | Does | Never |
|---|---|---|
| Lead | Picks slices by urgency, integrates, opens PRs, posts approval markers, keeps the progress file and tracker | Releases without the owner; lowers a gate; skips a test |
| Builder (agent, worktree) | One slice: code + tests tagged with test-plan IDs; pushes to its branch | Reviews its own work, opens PRs, posts on GitHub |
| Senior reviewer (fresh agent) | Reads the diff against the spec, test plan and prototype. Proves each finding with a throwaway test. Returns a VERDICT plus must-fix items with file:line, a scenario and a fix | Edits code |
| Security reviewer (fresh agent) | Same, for risky paths: import/parsing, AI payloads, storage/secrets, rendering of untrusted text, workflows, gate scripts, agent settings | Edits code |
| Deterministic tools | types, lint, tests + per-folder coverage, mutation testing (core logic), e2e (Playwright), audit | — |

Use a stronger model for money, security and migration work and for those reviews. Use a normal model for routine work.

## Lead decision rules
- **Keep fixing** when each attempt narrows the problem and the failure blocks urgent work. Cap it at 3 attempts or about 20 minutes.
- **Park** when it isn't narrowing or nothing depends on it. Record it in the progress file.
- **Ask the owner** for an ambiguous requirement, a product choice, a missing secret, or any "fix" that would weaken a gate. Ask **one question at a time**, always with a recommended default. Open a `needs-decision` issue as well if the answer must outlive the session.
- **Urgency order:** data safety and money correctness, then blockers, then core features, then polish.
- **Flaky tests:** find the root cause, such as un-awaited async work, timing races or time zones. Never retry until green. Never skip or disable a test.

## Gates on `main` (required checks)
`ci` (types, lint, tests, e2e), `coverage`, `mutation`, `review-gate`.
- **review-gate:** a commit status. It passes only when approval markers for the exact head SHA exist (`<!-- review:senior approve sha=… -->`, plus `review:security` when risky paths changed), posted by the owner, a member or a collaborator. A new commit invalidates the approval. The gate script runs from the base branch, and also on `workflow_dispatch` with a `pr` input.
- GitHub auto-merge does the merge once everything is green.

## Release workflow
Real-API check on synthetic data → full e2e on staging → publish the same build → production smoke test → tag. Any failure leaves production unchanged and is reported to the owner.

## Test data
100% synthetic, generated by a script, byte-reproducible, and shipped with expected results. **Mirror the real data's shape**: run a structure survey of the owner's existing data (field usage, statuses, how payments and links were recorded) before writing fixtures.

## Slice order
0. Gate the deploy (staging only, plus a Release skeleton).
1. Fixtures + harness.
2. Pipeline: coverage, mutation, review-gate, staging e2e, full Release.
3. Core logic, then data and migration, then features one per slice, then the shell and look, then polish plus a full scenario e2e.

## Owner setup checklist (exact click paths)
- Settings → General → **Default branch = main** (comment- and dispatch-triggered workflows run from the default branch).
- Rulesets → protect-main: PR required; required checks `ci`, `coverage`, `mutation`, `review-gate`; block force push and deletion.
- Allow auto-merge.
- Environment `release` (main only) with the API key secret, plus a monthly spend limit on that key.
- Claude session mode: **Auto**, plus allow-all in `.claude/settings.json`. Some tools still prompt; avoid them.
- The Lead verifies each item through the API where possible.
